## 1. Паспорт проекта

| Пункт | Решение |
|---|---|
| Пользователь | Продавец или контент-менеджер небольшого товарного каталога |
| Проблема | Характеристики находятся в таблице, тексты создаются отдельно; трудно сопоставлять ответы ИИ с товарами и понимать, какие карточки уже проверены |
| Цель | Из учебной товарной таблицы получить небольшой пакет вручную проверенных текстов с сохранённой привязкой к артикулам |
| Главный сценарий | Загрузить CSV → проверить исходные сведения → собрать запрос для Qwen → загрузить JSON-ответ → сверить и отредактировать текст → одобрить карточки → скачать CSV |
| Состав | Цифровой инструмент с текстами интерфейса, инструкцией и демонстрационными данными |
| Результат | Работающее приложение, демо на GitHub Pages, репозиторий, демоданные, проверенный экспорт и комплект выпускной работы |
| Категория MVP | Настольные органайзеры и лотки: одна небольшая категория с понятными характеристиками |
| Размер каталога | От 1 до 20 товаров; основной демонстрационный набор — 10 |
| Роль ИИ | Qwen создаёт черновики по переданным характеристикам; приложение собирает запрос и принимает структурированный ответ |
| Проверка содержания | Человек сопоставляет текст с исходными сведениями; автоматическая проверка контролирует формат и привязку, но не гарантирует истинность всех формулировок |
| Ограничения | Учебные товары; экспорт собственного формата; хранение в текущем браузере; ручной перенос ответа ИИ |

### Почему этот проект полезен для GitHub

В [README профиля](https://github.com/ergon73/ergon73/blob/main/README.md) уже обозначено направление подготовки данных и черновиков товарных карточек. CatalogDraft станет видимым пользовательским инструментом рядом с [парсером каталога](https://github.com/ergon73/ecommerce-catalog-scrapy-spider) и [синхронизацией остатков](https://github.com/ergon73/n8n-resilient-inventory-sync).

В кейсе показываем именно учебный результат. Клиентское внедрение, экономию времени и рост продаж без реальных измерений не заявляем.

## 4. Данные и правила — собственный бриф

Все приведённые ниже поля, ограничения и контрольные числа — **решения CatalogDraft**, а не требования Ozon, Wildberries или другой площадки. Они фиксируются в `docs/rules.md` до создания интерфейса.

### 4.1. Исходный CSV

Столбцы в фиксированном порядке:

```text
sku;name;material;color;width_cm;depth_cm;height_cm;pack_qty
```

| Поле | Правило |
|---|---|
| `sku` | Непустой уникальный артикул, до 40 символов; пробелы по краям убираются, регистр сохраняется |
| `name` | Название до 120 символов |
| `material`, `color` | Текстовые характеристики до 80 символов каждая |
| Размеры | Положительные числа до 100 см, максимум один знак после запятой; допустима точка или запятая, внутри используется одно нормализованное представление |
| `pack_qty` | Целое число от 1 до 100 |

Файл: UTF-8 с необязательным BOM, разделитель `;`, переводы строк LF или CRLF. Парсер поддерживает кавычки, удвоенные кавычки и перевод строки внутри поля. Максимум — 20 записей и 100 КБ. Это пределы MVP, которые видны до загрузки.

Два уровня ошибок:

1. **Ошибки файла:** неизвестный/неполный заголовок, нарушенная структура CSV, пустой или повторный `sku`, превышение размера/числа записей. Весь импорт отклоняется, прежняя работа сохраняется.
2. **Недостающие характеристики товара:** пустые `name`, `material`, `color`, размеры или количество; некорректное число. Каталог загружается для проверки, строка получает состояние «Нужны данные». Её нельзя включить в запрос или одобрить.

Исходные характеристики в приложении доступны для чтения. Для их исправления пользователь меняет CSV и загружает его заново. При загрузке изменённого каталога приложение предлагает скачать резерв и запрашивает подтверждение замены. Новый каталог получает новый `catalog_id`.

**Повторная загрузка того же нормализованного набора** ничего не сбрасывает: сравнение выполняется по артикулам и всем исходным полям, порядок строк несущественен. Сообщение: «Каталог уже загружен, изменения сохранены».

### 4.3. Состояния карточки

| Состояние | Условие |
|---|---|
| Нужны данные | Исходные характеристики неполны или некорректны |
| Готов к запросу | Характеристики полны, черновика нет |
| Черновик | Текст получен или изменён, но ещё не одобрен |
| Одобрено | Текст проходит формальные проверки, пользователь отметил сверку фактов и нажал «Одобрить» |

Счётчики показывают весь каталог. Поиск и фильтр меняют только видимую выборку. Число карточек во всех четырёх состояниях в сумме равно числу товаров.

Входящий JSON **не может одобрить карточку**. Любая правка одобренного текста снимает одобрение и отметку сверки. При отмене редактирования текст и прежнее состояние сохраняются. При уходе с несохранённой правкой показывается подтверждение внутри страницы.

### 4.4. Запрос и JSON-ответ Qwen

Один запрос содержит характеристики 1–3 выбранных товаров. В него попадают только данные, необходимые для текстов. Описание неизвестных свойств, рекламные гарантии и добавление характеристик не запрашиваются.

Пользователь видит и может скачать полный запрос. В интерфейсе явно написано: «Перенесите запрос в Qwen. Приложение не отправляет данные автоматически».

Формат ответа:

```json
{
  "format": "catalogdraft.response.v1",
  "catalog_id": "идентификатор из запроса",
  "cards": [
    {
      "sku": "ORG-001",
      "title": "Текст названия",
      "bullets": ["Короткий пункт о товаре"],
      "description": "Текст описания"
    }
  ]
}
```

В `docs/rules.md` закрепить:

- `catalog_id` создаётся при загрузке нового каталога и сохраняется вместе с ним; он не является секретом или ключом доступа;
- принимается только полный JSON указанного формата, без Markdown-ограждения и окружающего текста; при нарушении объясняется, какой файл требуется;
- верхние поля и поля карточек соответствуют контракту; лишние поля, включая `approved` или изменённые характеристики, отклоняются;
- от 1 до 20 карточек, без повторных или неизвестных артикулов;
- все артикулы относятся к товарам текущего каталога с полными характеристиками;
- название — 10–100 символов, 1–4 пункта по 10–160 символов, описание — 40–600 символов; пробелы по краям убираются;
- при любой ошибке весь ответ отклоняется, тексты и одобрения не меняются;
- при повторном импорте тех же текстов ничего не меняется, в том числе одобрения;
- изменённый текст для уже одобренной карточки применяется только после предупреждения и подтверждения; карточка становится черновиком;
- ответ с другим `catalog_id` отклоняется: «Ответ относится к другому каталогу».

**Формальная валидация не равна проверке фактов.** Даже корректный JSON остаётся черновиком. Человек проверяет соответствие размеров, материала, цвета и комплектации, отсутствие неподтверждённых обещаний и удобство текста.

### 4.5. Экспорт и резерв

CSV всегда содержит **все одобренные карточки текущего каталога**, независимо от фильтра на экране. Кнопка подписана «Экспорт одобренных (N)»; перед скачиванием виден состав выгрузки. При N = 0 объясняется, что сначала требуется одобрение.

Столбцы:

```text
sku;title;bullet_1;bullet_2;bullet_3;bullet_4;description
```

Кодировка UTF-8 с BOM; `;`; CRLF; корректное экранирование кавычек, разделителей и переводов строк. Неиспользованные пункты — пустые поля. Потенциальные формулы в текстовых ячейках нейтрализуются на этапе экспорта; исходные строки в приложении не переписываются. В README пояснить эту обработку. Это собственный формат передачи текстов, не готовый загрузочный шаблон конкретного маркетплейса.

Резерв JSON имеет отдельный формат `catalogdraft.backup.v1` и включает каталог, его идентификатор, черновики, отметки сверки и одобрения. Он не совпадает с форматом ответа модели. При восстановлении проверяется весь документ и все связи; некорректный резерв не меняет текущую работу. Перед заменой показываются число товаров и число одобрений, затем требуется подтверждение.

### 4.6. Хранение и ошибки

- Ключ localStorage: `catalogdraft.state.v1`.
- Первое открытие показывает пустой экран и два действия: «Загрузить CSV» и «Попробовать демо».
- После обновления восстанавливаются текущие данные, тексты и одобрения; поиск, фильтр и временные сообщения сбрасываются.
- При недоступном хранилище приложение продолжает работу в памяти и сообщает, что для сохранения нужен резерв.
- Повреждённое сохранение не заменяется молча демоданными. Показать проблему, предложить скачать исходное сохранённое содержимое, восстановить резерв или явно начать заново.
- Подтверждения и ошибки — внутри страницы, без системных `alert`, `confirm`, `prompt`.
- Повторный клик во время чтения файла не применяет импорт дважды; состояние операции видно пользователю.

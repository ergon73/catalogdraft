# Проверка CatalogDraft

Дата локального прогона: 05.11.2026. Проверялась реализация на Windows, Node 26.13.0, установленный Google Chrome через Playwright 1.64.1. Отдельный проход каталога, сверки и фактического скачивания CSV выполнен во встроенном браузере. Автоматические проверки не вызывают нейросети.

## Результат

- 13 модульных проверок — пройдены.
- 8 браузерных сценариев — пройдены, включая независимое открытие `file://`, обновление, скачанные файлы и новый browser context.
- Мобильная ширина 390 px — без горизонтального переполнения страницы; одобрение и экспорт доступны.
- Публичная версия [GitHub Pages](https://ergon73.github.io/catalogdraft/) открылась с пустым хранилищем. На ней пройдены демокаталог, три черновика, одобрение ORG-001 и обновление; скачанный CSV побайтово совпал с локальным браузерным результатом.
- [GitHub Actions: tests](https://github.com/ergon73/catalogdraft/actions/runs/42022135316) — success на исходном коммите приложения `3afa549`; [Pages build and deployment](https://github.com/ergon73/catalogdraft/actions/runs/42022167071) — success. CI выполняет Node 24 и Chromium на Ubuntu. Последующие изменения документации не меняют код приложения; актуальный статус workflow доступен по значку README.

## Итерация содержания

1. Исходник ORG-003 задавал «Материал: металл; цвет: чёрный».
2. Первый ответ Qwen назвал товар «Подставка «Ячейка», чёрный металл». Это неоднозначная формулировка, а не доказанный неверный состав материала.
3. Отдельным запросом уточнено только название, сохранив остальные поля.
4. В финальном ответе материал и цвет разделены. Сравнением подтверждено, что изменилось только это название; факты вновь сверены.
5. Итоговый ответ включён в демо. Исходный ответ и уточнение сохранены в рабочих материалах; запросы опубликованы в `docs/prompts.md`.

## Исправление интерфейса

При первом браузерном прогоне подтверждение замены каталога и восстановления резерва открывалось с недоступными кнопками: они унаследовали признак чтения файла `busy`. После полного разбора файла кнопки диалога теперь доступны. Сценарии отмены замены и подтверждённого восстановления проходят в браузере. Для ожидания окончания чтения используется наблюдаемое `aria-busy`, а не фиксированная задержка.

## Пределы проверки

Пройдены отдельные клавиатурные действия и семантические подписи; полный аудит экранной читалкой не выполнялся. Мобильный сценарий проверен эмуляцией, не физическим телефоном. Содержание трёх демотекстов сверено вручную; программа не обещает автоматическую проверку истинности произвольного ответа ИИ. Боевые данные магазина и интеграции площадок не использовались.
